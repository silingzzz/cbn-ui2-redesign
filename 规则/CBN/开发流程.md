# CBN 开发流程与验收体系

适用于 CBN UI 2.0 全部 PR。本文件定义流程，不定义技术约束（技术约束见 `AGENTS.md` 与 `模块规则\`）。

## 1. 十二步流程

| # | 环节 | 产出 / 判据 |
| --- | --- | --- |
| 1 | 需求确认 | 目标、范围、不做的事，写成一段话交用户确认 |
| 2 | 规则加载 | 读 `AGENTS.md`；涉及模块时读对应 `模块规则\`；`repo\` 内自动加载 `repo\AGENTS.md` |
| 3 | 现场检查 | `git status` / `git log` / 目标文件现状；确认没有未保存或他人改动 |
| 4 | 技术方案 | 基于源码事实，不基于猜测；不确定就先去读代码 |
| 5 | 实施计划 | 改动文件清单 + 每处改动理由 + 风险 |
| 6 | 最小修改 | 只改计划内文件；不顺手重构、不夹带格式化 |
| 7 | 编译验证 | 必须含 tiles 目标（和 `cata_test-tiles`）；记录命令与 exit code |
| 8 | 测试验证 | 相关 Catch2 用例 + 必要的冒烟；未跑就写“未测试” |
| 9 | 差异审查 | `git diff` 逐条过；确认无调试残留、无无关改动 |
| 10 | 文档与状态更新 | `docs\YYYY-MM-DD-CBN-…md` + `项目状态.md` |
| 11 | PR 验收 | 按验收方案逐项判定，用户确认 |
| 12 | 提交与收尾 | 原子提交、提交 ID 回填文档、更新状态 |

## 2. 四种状态，不许混用

| 状态 | 含义 | 证据 |
| --- | --- | --- |
| 代码已实现 | 文件已改 | `git diff` |
| 编译成功 | 目标产物生成 | 构建 exit 0 + 产物时间戳 |
| 测试通过 | 用例实际跑过 | 测试日志 + 用例数 |
| 正式验收 | 用户确认 | 验收报告 + 用户明确同意 |

**冒烟测试 ≠ 回归测试；编译通过 ≠ 功能可用；自测通过 ≠ 正式验收。**
任何文档、汇报、提交信息里不得把低阶状态描述成高阶状态。

## 3. 每个 PR 必填六项

1. **目标与范围**：要解决什么、改哪些文件、明确不做的事。
2. **不允许修改的边界**：列出禁改文件/模块（例如本 PR 不碰制作台、AIM、Zone）。
3. **技术实施方案**：基于源码现状的接入点、数据结构、失败模式。
4. **验收标准**：逐项可判定（通过/失败/未测），不用“应该可以”。
5. **测试要求**：必须跑的用例、必须人工操作的项。
6. **回滚方案**：改动是否可 `git checkout -- <file>` 单独回退；有无数据结构/存档影响。

## 4. 边界与红线

- 不擅自扩大架构改动；发现需要扩大时**先停**，报告后再动。
- 不改游戏存档格式与核心玩法逻辑（本系列只做 UI 层）。
- 不覆盖安装版目录、不改 `archive\src-mirror\`。
- 不执行 `git reset --hard` / `git clean` / 强制推送。
- 不删除历史文件与备份。
- 未获验收不进入下一 PR。

## 5. 文档落点

| 内容 | 位置 |
| --- | --- |
| 阶段记录 / 验收方案 / 验收报告 | `game\CBN-Development\docs\YYYY-MM-DD-CBN-<阶段>-<主题>.md` |
| 长期规则 | `规则\游戏\CBN\AGENTS.md` |
| 模块技术约束 | `规则\游戏\CBN\模块规则\<模块>\AGENTS.md` |
| 当前进度快照 | `规则\游戏\CBN\项目状态.md` |
| 长输出 / 日志 | `game\_out\` |
